RDP Clipboard Assessment — BeyondTrust PRA / Windows Server

Companion guide for Invoke-RdpClipboardAssessment.ps1: how to run it, how to read it, and which team owns each result.

1. What the script does

  • Runs from your laptop and uses the vCenter sessions you already have open ($global:DefaultVIServers). It does not reconnect.
  • Runs one read-only PowerShell payload in each guest through Invoke-VMScript (VMware Tools guest operations), signing in with C:\temp\wincred.xml. It does not use WinRM, PS Remoting, SSH or RDP.
  • Checks RDS clipboard and drive policies, RDP-Tcp listener flags, RDS services, sessions, whether rdpclip.exe runs in each session, application-control blocks, event logs and VMware Tools/console settings.
  • Writes C:\temp\RDP_Clipboard_Assessment_<timestamp>.xlsx (5 sheets) and a matching .log.
  • Resolves policy names and options from each server's own TerminalServer.admx/.adml, so nothing is assumed. For example, the directional clipboard-format policies are only evaluated on builds that define them.
  • Reads the Local GPO Registry.pol to show whether an effective value comes from Local Group Policy or was written straight to the registry (for example by a hardening script).

2. Execution instructions

Prerequisites (laptop only)

  • VMware PowerCLI (VMware.VimAutomation.Core), already connected to the vCenters.
  • ImportExcel module for the formatted workbook. Without it, the script writes 5 CSV files instead.
  • vCenter role with Virtual machine › Guest operations › Guest operation program execution / modifications / queries.
  • The guest account in wincred.xml should be the built-in Administrator, or another account with an elevated token. A UAC-filtered admin token is reported as WARNING, and checks it cannot read show as UNKNOWN.
Install-Module ImportExcel -Scope CurrentUser

Select and run

cd C:\path\to\script
# one VM
.\Invoke-RdpClipboardAssessment.ps1 -VMName APP01
# list of VMs (wildcards allowed)
.\Invoke-RdpClipboardAssessment.ps1 -VMName APP01,APP02,'SQL*'
# from file (one name per line, # = comment)
.\Invoke-RdpClipboardAssessment.ps1 -VMListFile C:\temp\vms.txt
# all eligible Windows Server VMs on all connected vCenters
.\Invoke-RdpClipboardAssessment.ps1 -AllWindowsVMs
# options: -EventLookbackDays 14  -IncludeWindowsClient  -OutputFolder C:\temp
Best evidence: keep a BeyondTrust RDP session to the affected VM open, try copying, and run the script for that VM while the session is connected. Only then can it show whether rdpclip.exe is running in the BeyondTrust session, which it identifies by the Jumpoint source address from LocalSessionManager events 21/25.

Automatic exclusions

Templates, vCLS and other solution-managed VMs, vApp/OVF appliances, non-Windows guests, Windows client OS (unless -IncludeWindowsClient), powered-off VMs, and VMs where Tools is not running or guest operations are not ready. Each skipped VM is listed with its reason on Errors and Skipped. A VM reached through two vCenter connections is counted once (keyed on its instance UUID).

Production safety

The script is read-only. It makes no registry, GPO, service, process, session, firewall, VM or BeyondTrust changes, installs nothing, and never logs credentials. The one write in the guest is the temporary script and output file that Invoke-VMScript creates and deletes in the guest account's %TEMP%. All VMware Tools guest operations do this. Corrective actions appear only as text in the report.

3. Interpreting results

StatusMeaningAction

Key evaluation rules

  • "Do not allow Clipboard redirection" = Enabled (fDisableClip=1) blocks clipboard. Disabled (0) allows it explicitly. Not Configured falls through to the RDP-Tcp listener flag.
  • When the computer policy is configured, it overrides the listener (Tsconfig) fDisableClip/fDisableCdm values.
  • Drive redirection (fDisableCdm, UmRdpService) affects files only. Text clipboard depends on rdpclip.exe and the clipboard policy.
  • rdpclip.exe is checked per active RDP session. If no RDP session is active, the check is NOT APPLICABLE, not FAIL.
  • TermService start mode Manual is the Windows default. Only "not Running" fails. UmRdpService and SessionEnv are on-demand services.
  • Firewall rules are informational only. Clipboard data travels inside the established RDP connection as a virtual channel.
  • VMware isolation.tools.copy/paste.disable controls the VMRC/web console clipboard only, never RDP. Do not change it for this issue.

Windows-side vs BeyondTrust-side

  • Windows-side (server team): any FAIL with Root-Cause Class Confirmed or Confirmed-Files.
  • BeyondTrust-side (PAM team): PAM Investigation Required = YES. Windows shows no confirmed text-clipboard blocker, so the remaining causes are the session policy, Jump Item, Jumpoint or console. Work through the PAM Verification sheet.
  • Laptop / security team: the Access Console version and elevation, and laptop DLP. Also any server with an Endpoint DLP indicator of UNKNOWN, which means MDE is present and Purview DLP may apply.

5. Limitations of the guest-script method

  • The payload runs in session 0 as the guest credential. It cannot see what the RDP client requested at connect time, so clipboard (CLIPRDR) and drive (RDPDR) channel negotiation is reported as UNKNOWN.
  • rdpclip.exe running in a session proves the server-side component is up, but not that BeyondTrust enabled the clipboard channel. rdpclip missing has several possible causes, so it is a WARNING, not a confirmed cause.
  • A non-elevated guest token can block reading some logs. Those checks become UNKNOWN.
  • Session parsing relies on qwinsta. On non-English OS builds it may return UNKNOWN.
  • Third-party DLP and clipboard agents cannot be detected generically. Only the Defender for Endpoint sensor is flagged, as a DLP indicator.
  • BeyondTrust settings cannot be read from the VM. They are listed on the PAM Verification sheet for the PAM team to complete.

6. Remediation script (Windows side)

Invoke-RdpClipboardRemediation.ps1 fixes the Windows-side blockers that the assessment confirms. It is a dry run by default. It changes nothing until you add -Apply, and then asks for confirmation on each VM.

# 1. dry run: see what would change
.\Invoke-RdpClipboardRemediation.ps1 -VMName APP01
# 2. apply the default fix (clipboard policy + listener)
.\Invoke-RdpClipboardRemediation.ps1 -VMName APP01 -Apply
# optional fixes (approval needed)
.\Invoke-RdpClipboardRemediation.ps1 -VMListFile C:\temp\fail.txt -Apply -FixClipboardFormatPolicies -FixDriveRedirection -StartRdpServices -RemoveRdpclipIfeo
# undo the last applied run on a VM
.\Invoke-RdpClipboardRemediation.ps1 -VMName APP01 -Rollback

  • Backup and rollback. Before any change, the script copies Registry.pol and gpt.ini and records each registry and service change in C:\Windows\Temp\RdpClipRemediation\<timestamp>\changes.json in the guest. -Rollback uses that file to restore the original state.
  • Registry.pol safety. The script edits Registry.pol only if it can read and rewrite the original file byte for byte. Otherwise it fixes only the live value and tells you to use gpedit.msc.
  • Values that can come back. If the bad value was not set by Local GPO (for example, a hardening script or baseline wrote it), or an MDM RDS policy exists, the report warns that the value may be re-applied.
  • No disruption, but users must reconnect. There is no reboot and no session disconnect, but settings apply only to new RDP sessions. Users must sign out and reconnect, then re-run the assessment during a live BeyondTrust session.
  • Credentials. Use an elevated guest credential (the built-in Administrator). Apply and rollback refuse to run without elevation.
  • Report. Results go to C:\temp\RDP_Clipboard_Remediation_<Mode>_<timestamp>.xlsx, with result values PLANNED, APPLIED, SKIPPED, NOT NEEDED, REPORT ONLY, FAILED and RESTORED.

7. PAM team checklist (summary of sheet 4)

  1. For the affected user and Jump Item, which policy wins (user, group policy, Jump Policy, or the Session Policy on the Jump Item), and what is the effective clipboard permission and direction?
  2. Is file transfer allowed for RDP sessions, separately from clipboard? In which directions, with what path restrictions, and does your PRA version support RDP file copy/paste?
  3. Jump Item properties: assigned Jumpoint, assigned Session Policy, and any RDP options affecting redirection.
  4. Jumpoint online, with a version that matches the appliance. Access Console version on the technician laptop.
  5. Session report for a failed session (session ID and time): which policy was applied, and any clipboard or file-transfer denials.
  6. Policy conditions (approval, schedule, location) that could apply a more restrictive variant.
  7. Evidence: screenshots or exports of each item above, plus the live-test matrix results.

BeyondTrust menu labels differ between PRA releases. The PAM team should match each item to the screens in your deployed version.
